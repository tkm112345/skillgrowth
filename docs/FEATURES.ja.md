# 機能一覧

English version: [FEATURES.md](FEATURES.md)

## ダッシュボード

- **キャリアパスの目標** — 今年/5年後/10年後の3つの自由記述欄。方向性があれば書く、という任意項目で、入力必須ではない。フォーカスが外れたタイミングで自動保存される。
- **近況メモ** — 「最近何をしていたか」を短い自由文で入力する欄。送信すると、他の証拠ソースと同じ経路でその場でスキル抽出が走る。
- **スキル成長タイムライン** — 各スキルの`first_observed_at`（初出日）から、累積スキル数の推移を階段状の折れ線グラフで表示する。
- **カテゴリ内訳** — カテゴリ別のスキル数を棒グラフで表示する。
- **スタッツ行** — 総スキル数・カテゴリ数・直近7日間の新規スキル数。あえてページ最下部に配置しており、主役は成長タイムラインと目標欄で、これらの数値は補助情報という位置づけ。

これらの目標をLLMによる提案につなげる機能は別ページに分離している（後述の**AI連携**を参照）。ダッシュボード自体はLLMを一切呼び出さない。

## プロフィール

- **リンク** — GitHub、X、note、Zenn、個人のブログ/ホームページなど、自分の活動や成果を示す外部リンクをラベル+URLで一覧登録できる。プラットフォームは固定リストではなく、ラベルは自由記述。
- **学歴** — 学校、学位、専攻、開始/終了日、自由記述の実績。
- **職歴** — 会社、部署、役割、開始/終了日（現職の場合は終了日を空欄にする）。
- **プロジェクト** — 名称、役割、開始/終了日、自由記述の内容。職歴に紐づけて表示することも（UI上でネストされる）、職歴に紐づかない個人プロジェクトとして単独登録することもできる。

ここでの自由記述欄（実績・プロジェクト内容）は、すべてスキル抽出にも使われる。リンクは単なる事実の記録であり、スキル抽出の対象にはならない。

「職務経歴書の取り込み」機能はあえて設けていない。個人の職務経歴書はフォーマットが人によってばらつきが大きく、LLMでの抽出精度に依存しすぎるため。スキルをまとめて登録したい場合は、スキル一覧画面のCSVインポートを使う。

## 学習ログ

正式な職務経歴の外側にあるキャッチアップ活動を記録する。

- **読書**、**登壇**、**聴講**、**資格**、**その他** — 固定の種別から選び、それぞれタイトル・日付・メモを持つ。
- 種別が**資格**の場合、証明書の画像を任意で添付できる。プロフィールの資格登録と同じ、画像ベースのビジョンモデルによるスキル抽出が走る。

## スキル一覧

- 証拠ログから導出された現在のスキル像を、名称・カテゴリ・証拠数・初出日・最終確認日として表示する。
- **スキルを直接追加** — 証拠はまだないが持っているとわかっているスキルを、名称・カテゴリを指定してそのまま登録できる。
- **CSVインポート** — `name,category`形式のCSVファイルからスキルをまとめて登録できる（`category`列は省略可）。
- どちらの方式も、既存スキルと大文字小文字を区別せずに重複排除される。スキルの削除も可能（そのスキルに紐づいていた証拠自体は残る）。

## アクティビティ

これまでに追加されたすべての証拠エントリ——近況メモ、資格証、および学歴/職歴/プロジェクト/学習ログの各自由記述部分——を、ソース種別のラベル付きで時系列に表示する読み取り専用のフィード。（手動追加・CSVインポートで登録したスキルは、背後に自由文が存在しないため、ここには表示されない。）このログは使い続ける限り増え続けるものなので、50件ずつ読み込み、「もっと見る」ボタンで続きを取得する。

## 職務経歴書

- **自己PR** — 自分自身についての自由記述のアピール文で、生成される職務経歴書の冒頭に含まれる。新しく入力しても過去の内容は上書きされず、すべて履歴として残る。職務経歴書の生成時には常に最新のものが使われる。
- **職務経歴書の生成** — 現在のスキル像・職歴/学歴・最新の自己PRを、決まった構成（自己PR→職歴→その他のプロジェクト→学歴→スキル→資格）のMarkdownに流し込むだけで組み立てる。**LLMは一切使わない**ため、LLM未設定でも動作する。UI上では生のMarkdownテキストではなく整形されたHTMLとして表示され、`.md`ファイルとしてダウンロードもできる。生成のたびにスナップショットとして保存されるため、過去のエクスポートも遡って閲覧できる（20件ずつ「もっと見る」で読み込み）。データがないセクションは出力からそのまま省かれる。

## AI連携

このアプリの中で、ユーザーの操作に応じてLLMを呼び出す機能はこの2つだけ（証拠を追加した際のスキル抽出は自動で別途LLMを使うが、こちらのページの操作とは別）。

- **成長ガイダンス** — ダッシュボードで記入したキャリアパスの目標それぞれについて、現在のスキルを踏まえて次に何を伸ばすべきかをLLMが提案する。文章が入力されている目標のみLLMを呼び出す。未入力なら何も送信されない。
- **求人票とのギャップチェック** — 求人票の文章を貼り付けると、LLMが現在のスキルと照合し、「既に満たしている項目」「不足している項目」、および短い所感を返す。

この2つを1つのページにまとめることで、アプリのどの部分がLLM任意（それ以外のすべて）で、どの部分がLLM必須（この2つだけ）かが一目でわかるようにしている。

## コンセプト

このプロダクトの基本ループと、4つの設計方針（セルフホスト・シングルユーザー／自由記述のスキル／LLMの差し替え可能性／自己評価ではなく証拠ベース）をアプリ内で確認できるページ。ループは直線ではなく円環として描いている: 証拠→抽出→スキル像→振り返り（LLM不使用の職務経歴書、または任意でAI連携ページの求人ギャップ/目標に向けた成長ガイダンス）→次の近況メモに書く内容へ。1周するたびに元の状態へ戻るのではなく、同じスキル像の上に少しずつ積み重なっていく。

## 設定

- **言語** — 英語と日本語を切り替えられる（ブラウザごとに記憶される。以前はトップバーにあった切り替えがここに移動した）。
- **LLM接続** — Base URL、APIキー、テキスト用モデル、画像用モデルをデータベースに保存し、UIから編集できる——`.env`の編集や再起動は不要。OpenAI互換のChat Completions APIであれば、クラウドAPIでもローカルのOllamaサーバーでも動作する。
- **接続テスト** — 保存前でも、フォームに入力中の値でそのまま疎通確認できる。APIキーやBase URLの入力ミスを、他の画面で失敗して初めて気づくのではなく、その場で発見できる。万一他の画面（近況メモ、成長ガイダンス、ギャップチェックなど）で失敗した場合も、LLMを呼び出す全エンドポイントが中身のない「Internal Server Error」ではなく、実際の失敗理由をエラー詳細として返す。
- **データのバックアップ** — 証拠ログ・スキル・プロフィール・目標・学習ログ・リンク・自己PR履歴・職務経歴書の生成履歴など、キャリアデータ全体を1つのJSONファイルとしてダウンロードできる。APIキーがバックアップファイルに残らないよう、LLM接続設定はあえて含めていない。
- **バックアップから復元** — 以前ダウンロードしたバックアップファイルをアップロードして取り込める。既存のデータを削除・上書きすることはなく、常に追加のみ。キャリア目標は、その期間がまだ空欄の場合にのみ埋める。
- **サンプルデータ** — ボタン1つで、架空の小さなキャリア履歴（スキル・近況メモ・キャリア目標・ネストされたプロジェクトを含む職歴・学歴・学習ログ・リンク・自己PR・職務経歴書のスナップショット）を、バックアップ復元と同じ取り込み経路で読み込める。LLMの設定や自分でデータを入力しなくても、職務経歴書の生成も含め、導入直後にアプリの見た目を確認できる。対になる**リセット**ボタンで、サンプル読込で追加された内容だけを正確に削除できる（IDで追跡しているため、何度読み込んでも、自分で入力したデータには一切影響しない）。AI連携ページの2機能のみ、引き続きLLM接続の設定が必要。

## 横断的な機能

- **多言語対応** — デフォルトは英語で、設定画面から日本語に切り替え可能（vue-i18n）。選択内容はブラウザごとに記憶される。
- **サイドバーの折りたたみ** — トップバーのボタンでサイドバーをアイコンのみの幅に縮小できる。状態はブラウザごとに記憶される。
- **ライト/ダークモード** — OS/ブラウザの設定に自動追従する。
- **カテゴリ/種別の色分け** — カテゴリ・学習種別・証拠のソース種別は、それぞれ名前のハッシュ値から8色のアクセントカラーのいずれかが決定論的に割り当てられる。ページごとに色の対応表を持たなくても、同じ名前は常に同じ色でアプリ全体に表示される。
- **バージョン表記** — サイドバー下部に表示。バックエンドの`/api/version`（リポジトリの`VERSION`ファイルを読んでいる）から取得しているため、実際にデプロイされているものとズレることがない。
