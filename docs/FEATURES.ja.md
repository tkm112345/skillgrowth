# 機能一覧

English version: [FEATURES.md](FEATURES.md)

> **用語について:** 以下で言う「スキル」はすべて、AIとしての「スキル」（Claude Code
> の Skill、LLMプラグイン、エージェントの能力など）ではなく、あなた自身のキャリア・
> 職務上のスキルを指します。README の用語注記も参照してください。

## ダッシュボード

- **キャリアパスの目標** — 今年/5年後/10年後の3つの自由記述欄。方向性があれば書く、という任意項目で、入力必須ではない。通常は読み取り専用のテキストとして表示され、「編集」ボタンで編集モードに入る。編集中は「キャンセル」で編集前の状態に戻せる（未保存の変更を破棄）か、「保存」で確定する。保存するたびに履歴として残り、上書きされることはない。各目標の「履歴」から過去の内容と日時を確認できる——一度に5件ずつ遅延読み込みし、「もっと見る」でさらに遡れるため、何年使っても画面が重くならない。
- **近況メモ** — 「最近何をしていたか」を短い自由文で入力する欄。送信すると、他のアクティビティソースと同じ経路でその場でスキル抽出が走る。
- **スキル成長タイムライン** — 各スキルの`first_observed_at`（初出日）から、累積スキル数の推移を階段状の折れ線グラフで表示する。
- **カテゴリ内訳** — カテゴリ別のスキル数を棒グラフで表示する。
- **スタッツ行** — 総スキル数・カテゴリ数・直近7日間の新規スキル数。あえてページ最下部に配置しており、主役は成長タイムラインと目標欄で、これらの数値は補助情報という位置づけ。

これらの目標をLLMによる提案につなげる機能は別ページに分離している（後述の**AI連携**を参照）。ダッシュボード自体はLLMを一切呼び出さない。

## ビジョン

構成も期間の区切りもなく、どういうキャリアを目指したいのかをざっくりと書き記す、自由記述の1枠だけのページ。ダッシュボードの3つのキャリアパスの目標よりもさらに緩やかな位置づけで、目標が「いつまでに・何を」を問うのに対し、ビジョンは何も問わない。値は1つだけ（リストではなく単一の値）で、前回保存した内容が入った状態で表示され、保存するとその場で上書きされる——キャリアパスの目標とは異なり、過去のバージョンは履歴として残らない。キャリアパスの目標と同じく、LLM(抽出を含め)は一切関与しない単なるテキストで、アクティビティのフィードにも表示されない。

## セルフフィードバック

構造化された定期的な振り返りのための専用ページ。独立したエンティティ（`SelfFeedback`）で、アクティビティログとは別枠——ビジョンやキャリアパスの目標と同じく、証跡には紐づかずスキル抽出の対象にもならない。ダッシュボードにあった旧「振り返り」カード（タイムスタンプと任意コメントだけを記録する軽量な仕組み）を置き換えた。

- **記録を追加** — 日付（週次/月次のような構造は課さず、自由に選べる）と、横並びの3つのテキストエリア（やったこと・所感や反省・次に活かすこと）。3つとも空の間は追加ボタンが無効化される。
- **過去の記録** — 新しい順に一覧表示され、追加フォームと同じ3列レイアウトで表示、50件ずつ「もっと見る」で読み込む。追記型のアクティビティログとは異なり、ここでは日付・3項目すべてを**編集**（ダイアログ経由）でき、**削除**もできる——個人的な日記であり、監査記録ではないため。

## プロフィール

- **リンク** — GitHub、X、note、Zenn、個人のブログ/ホームページなど、自分の活動や成果を示す外部リンクをラベル+URLで一覧登録できる。プラットフォームは固定リストではなく、ラベルは自由記述。
- **学歴** — 学校、学位、専攻、開始/終了日、自由記述の実績。
- **職歴** — 会社、部署、役割、開始/終了日（現職の場合は終了日を空欄にする）。
- **プロジェクト** — 名称、役割、開始/終了日、自由記述の内容。職歴に紐づけて表示することも（UI上でネストされる）、職歴に紐づかない個人プロジェクトとして単独登録することもできる。

ここでの自由記述欄（実績・プロジェクト内容）は、すべてスキル抽出にも使われる。リンクは単なる事実の記録であり、スキル抽出の対象にはならない。

「職務経歴書の取り込み」機能はあえて設けていない。個人の職務経歴書はフォーマットが人によってばらつきが大きく、LLMでの抽出精度に依存しすぎるため。スキルをまとめて登録したい場合は、スキル一覧画面のCSVインポートを使う。

## ポートフォリオ

Webリンク・PDF・表計算ファイル・写真といった成果物や作品サンプルを、プロフィールの学歴/職歴/プロジェクトとは切り離して管理する。学歴/職歴の情報を伴わずに人に見せられるようにするための場所。

- 各成果物はタイトル・自由記述の説明（このアプリの他の自由記述欄と異なり、**スキル抽出の対象にはしない**）・任意の数のリンク（ラベル+URL）・任意の数のアップロードファイルを持てる。アップロードできるのはPDF・表計算ファイル（.xlsx/.xls/.csv/.ods）・写真（.jpg/.jpeg/.png/.gif/.webp）——このページの用途に合わせた形式に限定している。1ファイルあたり10MBまで。
- プロフィールの既存プロジェクトに任意で紐付けられるが、**会社（職歴）に紐づいていない、独立したプロジェクトのみ**選択できる。これはUI上でドロップダウンから隠しているだけでなくサーバー側でも強制しており、成果物から勤務先が特定されることはない。
- データのバックアップ/復元の対象に含まれ、アップロードしたファイルの実体もそのまま埋め込まれる（Wordテンプレートと同じ扱いで、意図してアップロードしたファイルが復元時に失われないようにするため）。

## スキル一覧

- アクティビティログから導出された現在のスキル像を、名称・カテゴリ・アクティビティ数・初出日・最終確認日として表示する。
- **スキルを直接追加** — アクティビティはまだないが持っているとわかっているスキルを、名称・カテゴリを指定してそのまま登録できる。
- **CSVインポート** — `name,category`形式のCSVファイルからスキルをまとめて登録できる（`category`列は省略可）。
- どちらの方式も、既存スキルと大文字小文字を区別せずに重複排除される。
- **編集** — スキルの名称・カテゴリをその場で直接編集できる。LLMの抽出ミス（誤字や、分類してほしいカテゴリと違う場合など）を、削除して登録し直さずに直せる。別の既存スキルと大文字小文字を区別せず同名になる変更は、暗黙に統合されず拒否される。
- スキルの**削除**も可能（そのスキルに紐づいていたアクティビティ自体は残る）。
- **職務経歴書に含む** — 各行のスイッチで、そのスキルを生成される職務経歴書の「スキル」セクションに載せるかどうかを切り替えられる。デフォルトはオン。今は使っていない技術や、単独の箇条書きにすると伝わりにくいソフトスキルなど、トラッキングはしたいが応募先には見せたくないスキルをアプリ内には残したまま、職務経歴書だけから外すのに使える。オフにしてもアプリの他の部分（スキル一覧やアクティビティなど）からは消えず、職務経歴書のテンプレートだけがこの設定を見る。

## アクティビティ

キャッチアップ活動の追加と、これまでの記録の閲覧を1つの画面にまとめている。以前は学習ログという別ページと、同じ内容を表示する読み取り専用のフィードが分かれていて内容が重複していたため統合した。

- **アクティビティを追加** — 種別を選び、タイトル・日付・メモを入力する。種別はフィールド横の「種別を管理」からユーザー自身で管理できる——初期状態で5種類（読書・登壇・聴講・資格・その他）がシードされ、資格以外はいつでも改名・削除でき、新しい種別も自由に追加できる（削除しても選択肢から消えるだけで、既存の記録はテキストとしてそのまま残る）。**資格**だけは組み込みの保護された種別で、職務経歴書の資格セクションに反映されるほか、証明書画像の任意添付欄（プロフィールの資格登録と同じ画像ベースのビジョンモデルによるスキル抽出が走る）が開くため、改名・削除はできない。
- **フィード** — これまでに追加されたすべてのアクティビティエントリ——近況メモ、資格証、学歴/職歴/プロジェクトの各自由記述部分、および上記フォームから追加した内容——を、ソース種別のラベル付きで時系列に表示し、「2026年9月」のような年/月の見出しでグループ化する。このログは使い続ける限り増え続けるものなので、50件ずつ読み込み、「もっと見る」ボタンで続きを取得する（グループ分けは読み込み済みの分だけをその場で計算するため、続きを読み込むまでは1つのグループが途中までしか揃わないことがある）。（手動追加・CSVインポートで登録したスキルは、背後に自由文が存在しないため、ここには表示されない。）
- **月へ移動** — ブラウザに読み込み済みの内容ではなく、サーバー側の集計に基づいて年ごとにグループ化され、月ごとの件数付きで表示されるドロップダウン。月を選ぶと、フィードがその月のエントリだけに置き換わる（月の中ではやはり50件ずつページング）。選択を解除すると通常の新しい順フィードに戻る。この仕組みのおかげで、ログが何年分も溜まっても、間のすべてを読み込まずに古い月へ直接ジャンプできる。
- **削除** — 上のフォームから追加したエントリにのみ表示され、押すとその種別・タイトル・日付といった構造化データが削除される。エントリ自体はテキストとしてフィードに残る——アクティビティログは、アプリの他の場所（学歴・職歴・プロジェクトの削除など）と同じく追記型の設計のため。

## 職務経歴書

- **自己PR** — 自分自身についての自由記述のアピール文で、生成される職務経歴書の冒頭に含まれる。新しく入力しても過去の内容は上書きされず、すべて履歴として残る（下の職務経歴書のスナップショットと同じく、10件ずつ「もっと見る」で読み込む）。新しく追加したものは自動的に職務経歴書で使われる版になるが、過去のどのバージョンも「このバージョンを使用」でいつでも選び直せる——新しい下書きを書いても、それをすぐ使わせられるわけではない。各エントリはその場で**編集**もできる（誤字の修正のために新しいエントリを作る必要はない）。現在職務経歴書に反映されているエントリには「使用中」と表示される。
- **職務経歴書の生成** — 現在のスキル像・職歴/学歴・選択中の自己PRを、決まった構成（自己PR→職歴→その他のプロジェクト→学歴→スキル→資格）のMarkdownに流し込むだけで組み立てる。**LLMは一切使わない**ため、LLM未設定でも動作する。UI上では生のMarkdownテキストではなく整形されたHTMLとして表示され、`.md`ファイルとしてダウンロードもできる。生成のたびにスナップショットとして保存されるため、過去のエクスポートも遡って閲覧できる（20件ずつ「もっと見る」で読み込み）。データがないセクションは出力からそのまま省かれる。
- **スナップショットの編集** — 最新に限らず過去のどの職務経歴書も、生のMarkdownとして直接編集できる（「編集」でレンダー表示からテキストエリアに切り替え）。テンプレートだけでは整いきらない言い回しの調整や、特定の応募先向けに1件だけ手を加えたい場合に、改めて生成し直さなくて済む。編集済みのスナップショットは生成日時と編集日時の両方が表示される。
- **Wordテンプレート出力** — 上記のMarkdown版とは別に、`{{p self_pr }}`のようなタグを埋め込んだ`.docx`ファイルをアップロードしておくと、そのタグの位置に現在のデータを展開したファイルをその場で生成できる（アプリ内のタグ一覧パネルに、利用可能な6種類のタグと正確な書き方が表示される）。上のMarkdown生成と同じく決定論的で、LLMは一切使わない。テンプレートは複数保存・切り替えでき、1つをデフォルトに指定できる。職歴・プロジェクト・スキル・資格の4セクションは、それぞれ箇条書きかWordのネイティブなテーブルかを選べる——テンプレートファイル側のロジックを書き換えるのではなく、UI上のドロップダウンでテンプレートごとに選択する方式なので、同じ`.docx`のデザインのまま、あるときはテーブルで、あるときはリストで出力する、といったことがテンプレートを2つ用意せずに実現できる。

## AI連携

このアプリの中で、ユーザーの操作に応じてLLMを呼び出す機能はここだけ（アクティビティを追加した際のスキル抽出は自動で別途LLMを使うが、こちらのページの操作とは別）。

- **キャリア相談** — スキル・アクティビティ・学歴・職歴・自己PR・ビジョン・キャリアパスの目標といった実際のデータを踏まえて、AIキャリアコンサルタントとチャットできる。メッセージを送るたびにこれらのデータが毎回コンテキストとして渡されるため、一般論ではなく自分自身に即したアドバイスになる。会話は保存され、このページに一覧（最初のメッセージから自動生成されたタイトル付き）が並び、後から再開したり削除したりできる。下の2機能が単発のリクエスト/レスポンスなのに対し、こちらは本当の意味での複数ターンの会話——返信のたびにその会話の全メッセージ履歴を送り直すため、やり取りを重ねてもAIが文脈を保持する。メッセージ自体は保存済みで、AIの返答だけが失敗した場合（LLM接続の不調など）でも、書いた内容が失われることはない。「このコンサルタントをカスタム」欄（デフォルトで折りたたみ）から、口調や重視してほしい観点などの追加指示を基本のシステムプロンプトに足せる。あえてキャリア相談だけに絞っている——下の2機能はLLMの返答から厳密なJSON形式を読み取っており、プロンプトを自由に書き換えられるとそのパースが壊れる恐れがあるが、キャリア相談は自由文のチャットなので壊れるものが無い。
- **成長ガイダンス** — ダッシュボードで記入したキャリアパスの目標それぞれについて、現在のスキルを踏まえて次に何を伸ばすべきかをLLMが提案する。文章が入力されている目標のみLLMを呼び出す。未入力なら何も送信されない。
- **求人票とのギャップチェック** — 求人票の文章を貼り付けると、LLMが現在のスキルと照合し、「既に満たしている項目」「不足している項目」、および短い所感を返す。

この3つを1つのページにまとめることで、アプリのどの部分がLLM任意（それ以外のすべて）で、どの部分がLLM必須（この3つだけ）かが一目でわかるようにしている。

## コンセプト

アプリ内でコンセプトを確認できるページ。冒頭は**なぜこのツールがあるのか**——キャリア情報は結局いつもリクルーターのサイトや会社の内部システムなど他人のプラットフォームの上に置かれ、本当の意味で自分のものになったことがない。だからこそskillgrowthは、転職活動や会社の評価タイミングに強制されてはじめて考えるのではなく、自分自身のサーバー上でキャリアの記録を所有し育て続けられるように存在する（README.mdの「Why」セクションと同じ説明）——から始まり、続けてこのプロダクトの基本ループと、5つの設計方針（セルフホスト・シングルユーザー／自由記述のスキル／LLMは任意で必須ではない／LLMの差し替え可能性／自己評価ではなくアクティビティベース）を確認できる。

ループは5つのステップから成り、最初の4つは円環として、5つ目だけ別枠の分岐として描いている:

1. **ビジョン** — ビジョンやダッシュボードで、どんなキャリアを築きたいかをざっくり書く。
2. **記録・更新** — 今持っているスキルやアクティビティを継続的に記録・更新する。
3. **蓄積** — 学歴・職歴、会社でのプロジェクトやOSS活動などを記録する。
4. **振り返り** — セルフフィードバックで、やったことと足りないものを見返す。

4はそのまま1に戻ります——これがメインの流れで、円環として閉じた形で描いている部分です。5（**準備** — 職務経歴書の生成、求人ギャップチェック、目標に向けた成長ガイダンス、そして新設のキャリア相談）は、あえてこの円環には含めていません。4からの「ときどきの寄り道」であり、1周するたびに必ず通るステップではないため、別枠の分岐として描いています。ここでの「LLMを使う機能はまだ十分な検証ができていない」という注記は、機能自体が未実装という意味ではありません——どれも実際に動く機能です。あくまで、このアプリがまだ十分な実運用実績を積んでおらず、LLMの提案の質を保証できる段階ではない、という信頼性についての但し書きです。

ダッシュボード・プロフィール・アクティビティ・スキル一覧など、このアプリの多くの画面は同じ追記型のアクティビティログを異なる角度から見ています。一方でビジョン・キャリアパスの目標・セルフフィードバック・自己PR・職務経歴書の生成そのものはこのログの外側にあり、どの段階でもLLMによる抽出には関与しません。

## 設定

- **表示** — 言語（英語/日本語）、テーマ（システムに合わせる/ライト/ダーク）、アプリの8色パレットから選ぶテーマカラー。3つとも即座に反映されるブラウザローカルの設定（`localStorage`）で、互いに独立している——ダークモードを選んでもテーマカラーはリセットされない。
- **LLM接続** — Base URL、APIキー、テキスト用モデル、画像用モデルをデータベースに保存し、UIから編集できる——`.env`の編集や再起動は不要。OpenAI互換のChat Completions APIであれば、クラウドAPIでもローカルのOllamaサーバーでも動作する。一度設定すると、以降はAPIキーが平文で画面に表示されることはなく、固定のプレースホルダーとして表示される。他の項目だけ変更して保存したり接続テストしたりしても（APIキー欄を触らなければ）、プレースホルダーで上書きされることなく保存済みのキーがそのまま使われる。
- **スキル抽出トグル** — 近況メモ・アクティビティ・プロフィールの自由記述（学歴/職歴/プロジェクト）からのスキル抽出LLM呼び出しを一括でオン/オフできるスイッチ（**デフォルトはオフ**）。オフの間はこれらの保存がLLM呼び出しなしで即座に完了する。オンにすると自由記述から自動的にスキルを抽出できる代わりに、保存のたびにLLMの応答を待つことになる。資格画像からの抽出は別経路のため、この設定に関わらず常に実行される。
- **接続テスト** — 保存前でも、フォームに入力中の値でそのまま疎通確認できる。APIキーやBase URLの入力ミスを、他の画面で失敗して初めて気づくのではなく、その場で発見できる。万一他の画面（近況メモ、成長ガイダンス、ギャップチェックなど）で失敗した場合も、LLMを呼び出す全エンドポイントが中身のない「Internal Server Error」ではなく、実際の失敗理由をエラー詳細として返す。
- **データのバックアップ** — アクティビティ・スキル・プロフィール（学歴/職歴/プロジェクト）・履歴付きの目標・ビジョン・セルフフィードバック・アクティビティ種別・リンク・自己PR履歴・職務経歴書の生成/テンプレート履歴・ポートフォリオ（成果物/リンク/ファイル）・キャリア相談の会話履歴を含む、キャリアデータ全体を1つのJSONファイルとしてダウンロードできる。APIキーがバックアップファイルに残らないよう、LLM接続設定はあえて含めていない。
- **バックアップから復元** — 以前ダウンロードしたバックアップファイルをアップロードして取り込める。既存のデータを削除・上書きすることはなく、常に追加のみ。キャリア目標とビジョンは、まだ空欄の場合にのみ埋める。
- **サンプルデータ** — ボタン1つで、架空の小さなキャリア履歴（スキル・近況メモ・キャリア目標・ビジョン・ネストされたプロジェクトを含む職歴・学歴・読書/登壇/資格などのアクティビティ・リンク・自己PR・職務経歴書のスナップショット）を、バックアップ復元と同じ取り込み経路で読み込める。LLMの設定や自分でデータを入力しなくても、職務経歴書の生成も含め、導入直後にアプリの見た目を確認できる。対になる**リセット**ボタンで、サンプル読込で追加された内容だけを正確に削除できる（IDで追跡しているため、何度読み込んでも、自分で入力したデータには一切影響しない）。AI連携ページの3機能のみ、引き続きLLM接続の設定が必要。
- **アプリについて** — アプリ名とバージョン（`/api/version`から取得）、ライセンスをモーダルで表示する。issue/PRの導線はサイドバーのCONTRIBUTEボタン（後述の横断的な機能を参照）に移動し、設定画面だけでなくどのページからでも見えるようにした。

## 横断的な機能

- **サイドバーの折りたたみ** — トップバーのボタンでサイドバーをアイコンのみの幅に縮小できる。状態はブラウザごとに記憶される。スマートフォン幅（768px以下）での初回訪問時はデフォルトで折りたたみ状態になる——展開したままだと画面幅の半分近くをサイドバーが占有してしまうため。一度どちらかに切り替えると、以降は画面幅に関わらずその明示的な選択が優先される。
- **カテゴリ/種別の色分け** — スキルのカテゴリとアクティビティのソース種別は、それぞれ名前のハッシュ値から8色のアクセントカラーのいずれかが決定論的に割り当てられる。ページごとに色の対応表を持たなくても、同じ名前は常に同じ色でアプリ全体に表示される。
- **バージョン表記** — サイドバー下部に表示。バックエンドの`/api/version`（リポジトリの`VERSION`ファイルを読んでいる）から取得しているため、実際にデプロイされているものとズレることがない。
- **CONTRIBUTE** — どのページでもサイドバーのコピーライト表記の直上に目立つボタンを配置し、GitHubリポジトリへのリンクとissue作成への導線を含むモーダルを開く。skillgrowthはMITライセンスのオープンソースで、設定の奥に隠すのではなく、本当に見つけやすい場所に置くことを意図している。
